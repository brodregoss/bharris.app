Prompt 1 — Generate triage terms

Trigger: source.items empty. count = min(source.terms || 12, 15). Schema: array of { term, definition, difficulty, depends_on }.

You are building a last-minute study triage for a student about to cram "{sourceTitle}". Generate exactly {count} key terms/concepts a student must know for this exam. For each term provide: term (short name), definition (one concise sentence), difficulty (integer 1-10, 10 = hardest), depends_on (array of OTHER term names from your list that this concept builds upon; foundational concepts others rely on should have empty or few dependencies, advanced concepts should reference foundational ones). Include a healthy mix of foundational and advanced concepts. Return exactly {count} terms.
Prompt 2 — Grade short answer

Trigger: student submits a typed answer and localGradeShortAnswer did not already mark it correct. Schema: { correct: boolean, feedback: string }.

You are grading a student's short-answer response for an exam-prep app.
Term: {q.term}
Correct definition: {q.definition}
Student's answer: {shortAnswer}

Mark correct if the student shows the same meaning — ignore case, punctuation, extra words, and wording. If they restated the term or the definition, that is correct. Only mark incorrect when the meaning is wrong.
Respond with JSON { "correct": boolean, "feedback": "one short sentence" }.
Prompt 3 — Explain a wrong short answer

Trigger: student taps Explain after grading. Free-text, not JSON.

A student is studying the term "{q.term}". The correct definition is: "{q.definition}". The student answered: "{shortAnswer}". In 2-3 short sentences, explain the concept clearly so the student understands why the correct definition is the right answer. Focus on helping them understand the correct answer.
Prompt 4 — Explain-it (teach) grade

Trigger: explanation length ≥ 20. Schema: { level, points_hit, points_missed, feedback }. Level 4 cannot be awarded for a short paraphrase.

You are grading whether a student can TEACH a concept, not whether they can recite a definition.
Term: {current.term}
Correct meaning: {current.definition}
Related ideas: {depends_on joined, or "none listed"}
Student explanation:
{text}

Score 1–4:
1 Guess — vague, mostly wrong, or just restates the term.
2 Getting there — some correct ideas, missing important points.
3 Solid — would help a classmate; a few gaps.
4 Mastered — teaches it fully: what it is, why it matters, and the key related points, as if explaining to a beginner. Do not give 4 for a short paraphrase of the definition.
Return JSON { "level": 1-4, "points_hit": ["..."], "points_missed": ["..."], "feedback": "one or two sentences" }.
Prompt 5 — Panic notes page

Trigger: Generate / Regenerate. Payload = Critical+Core terms with confidence, missed count, testResult, depends_on. No JSON schema — markdown string.

You are writing last-minute exam cram notes for a student who is out of time. Below is a JSON array of the terms they must know, each with how well they currently know it. Write ONE cohesive page of study NOTES (not flashcards, not a definitions list) meant to be read straight through in a few minutes.

Rules:
- Open with the concepts they're weakest on (confidence "blank", many "missed", or tested false) — explain each plainly and fully, as if explaining to a friend in one breath. Bold the term name.
- Then a tighter refresher for "shaky" concepts.
- End with a one-line "You've got these:" list naming mastered concepts (confidence "know", few misses) — no explanations.
- Skip any term whose tier is "passive".
- Plain, casual language. Short paragraphs and bullet groups. No filler, no pep talks.
- Where depends_on shows a foundation, explain it before the concept that builds on it.
- Use markdown: "## Know these cold", "## Quick refresh", "## You've got these".

4. Algorithms — math and execution order

Deterministic code paths. Hover the header box, then read the execution steps.

Session length

studyUtils + StudyFlow

totalMs = max(15 × 60 × 1000, hours × 3_600_000) timeRemainingMs = totalMs − (now − sessionStart)

Block budgets (except Passive, which uses exam-type ratio):

critical = 0.40 · totalMs core = 0.30 · totalMs passive = 0.10 · totalMs (MCQ 0.12, short-answer 0.07) test = 0.15 · totalMs confidence = 0.05 · totalMs

Triage ranking (pre-lock-in)

Triage.jsx · rankTerms

Execute

  1. For each term T, depCount[T] = number of other terms whose depends_on lists T’s name.
  2. maxDiff = max(difficulty), maxDep = max(depCount) (floored at 1).
  3. Score and sort descending:
priority(T) = (difficulty(T) / maxDiff) × 0.6 + (depCount[T] / maxDep) × 1.2 blankEnd = max(1, round(n × 0.35)) shakyEnd = blankEnd + max(1, round(n × 0.35))

Index 0 … blankEnd−1 → Blank; blankEnd … shakyEnd−1 → Shaky; rest → Know it.

On Lock in (two independent axes):

confidence = know_it → "know", else the column id ("blank"|"shaky") studyTier = tierFromDifficulty(difficulty, examType)

tierFromDifficulty

studyUtils.js

examTypeCriticalCorePassive
MCQd ≥ 8d ≥ 5else
Short answerd ≥ 8d ≥ 4else
Mixed (default)d ≥ 7d ≥ 4else

In-session priority

priority(term)

TIER_WEIGHT = { critical: 3, core: 2, passive: 1 } CONF_WEIGHT = { blank: 3, shaky: 2, know: 1 } priority = TIER_WEIGHT[tier] × CONF_WEIGHT[confidence]

Recall card style

RecallBlock.jsx · cardStyle

MCQ: i % 4 === 3 → recognition, else free_recall Short answer: i % 5 === 4 → explain, else free_recall Mixed: i % 2 === 1 → recognition, else free_recall

Recognition distractors (pickRecallDistractors): prefer terms sharing a depends_on concept, then same study tier, then any other term. Unique definitions, n=3, then shuffle with the correct def.

Got it (multi-pass): correctStreak += 1. If streak ≥ retireThreshold (Critical 2, else 1), drop from queue. Else advance; wrap increments round.

Missed (multi-pass): streak = 0; remove from current index; reinsert at

offset = 3 + floor(random × 4) // 3, 4, 5, or 6 insertAt = min(pos + offset, queue.length)

singlePass (confidence 5-min drill): always advance pos; no requeue; retireThreshold 1; finish when pos ≥ length or 5 min.

Block also ends if blockBudgetMs elapses (reason: 'time').

Passive time guard

StudyFlow.goPassive

remaining = totalMs − (now − sessionStart) protected = testBudget + 0.05·totalMs passiveB = totalMs × passiveRatioFor(examType) sensitivity = short_answer ? 0.8 : mcq ? 1.3 : 1.0 if remaining < (passiveB + protected) × sensitivity behind ← true

buildQuestions

PracticeTest.jsx

N = min(terms.length, 12) sort key 1: missed ? 0 : 1 sort key 2: critical=0, core=1, passive=2 take first N type = mixed ? (i even → mcq, i odd → short) : multiple_choice → mcq : short per-question timer: mcq 30_000 ms · short 90_000 ms overall cap: 0.15 · totalMs expiry without answer → recorded incorrect, auto-next

localGradeShortAnswer

studyUtils.js

normalize(s) = lower(s), strip non-letters/digits to spaces, collapse space if normalize(student) === normalize(definition) → correct if shorter.length ≥ min(4, def.length) AND longer includes shorter → correct else → null (fall through to LLM)

computeReadiness

studyUtils.js

rt = retireThreshold(tier) // 2 if critical else 1 m = min(1, correctStreak / rt) if seen: m = max(m, 0.15) if testResult true: m = 1 if testResult false:m = max(0, m − 0.3) readiness = round( 100 × Σ (TIER_WEIGHT[t] · m_t) / Σ TIER_WEIGHT[t] )

isTermShaky

studyUtils.js

True if any of:

  • id ∈ stillShaky (missed on the practice test)
  • confidence is blank or shaky
  • any recallHistory result === 'missed'
  • tier is critical/core and correctStreak < retireThreshold

withinStopWindow

studyUtils.js

if examTiming === "today" OR stopTime missing → false stop = today at HH:MM from stopTime active iff now ≥ stop − 45 × 60 × 1000 WIND_DOWN_BUDGET_MS = 12 × 60 × 1000 SKIP_ON_WIND_DOWN = passive, passive_summary, test, test_summary → force phase confidence

Mastery machine

mastery.js

Infer from a finished cram (never infers 4):

testResult false OR any missed recall → 1 Guess confidence blank → 0 testResult true OR streak ≥ retireThreshold → 3 Solid confidence know → 2 confidence shaky → 1 else → 0

bumpFromPractice (flashcards / practice test):

correct: if now=0 → 2; else min(3, now+1); 4 stays 4 wrong: if now=4 → 3; if now=0 → 1; else max(1, now−1)

userSetMastery: allow 0–3 only. Requesting 4 is ignored.

sortForPractice: lowest mastery first, then A–Z.

localExplainLevel (LLM down):

words = definition tokens with length > 3 ratio = (# of those words found in answer) / |words| ratio ≥ 0.7 AND answer has ≥ 12 words → 3 ratio ≥ 0.4 → 2 else → 1 (never 4 locally)

panicSignature

panicCache.js

for each term where tier ∈ {critical, core}: piece = id|tier|confidence|correctStreak|testResult|recallResultsJoined signature = pieces joined by ";;"

6. StudyFlow phase machine

notes_offer → notes_skim? → critical → critical_summary → core → core_summary
    → passive → passive_summary → test → test_summary → confidence → home

Wind-down: if withinStopWindow, skip passive/test (and summaries) → confidence.
Critical/core while wind-down: queue = shaky terms only, budget 12 min, retire 1.

Cheat sheet button: phases critical | core | test | confidence.
